01 / Problem會議後的斷點

企業現場問題

會議不會總是直接說「誰要做什麼」

真實逐字稿常是討論、抱怨、風險、時間點與依賴關係混在一起。會後若靠人手整理，任務容易遺漏，owner 判斷不一致，追蹤也分散在訊息串與口頭提醒。

Leakage

行動項目漏接

逐字稿沒有明確責任人時，PM 需要重新推理誰最適合承接，容易漏掉高風險事項。

Routing

派工規則不一致

不同主持人用不同邏輯派給不同人，企業規模放大後難以稽核。

Follow-up

催辦沒有閉環

GitLab issue、Slack 提醒與會議紀錄分散，管理層看不到狀態落差。

目標：把討論變成有 owner、有依據、有狀態的工作流02
02 / Before After從人工追逐到系統監工

Product Shift

同一份會議記錄，輸出不同管理結果

Before
  • 主持人人工讀逐字稿，靠記憶整理待辦。
  • 誰負責由當下判斷決定，缺少一致規則。
  • GitLab issue 需要手動建立，Slack 需要另開訊息。
  • 追蹤靠人肉催促，管理者只能問進度。
After
  • AI 從討論中拆解工作、風險、期限與依賴。
  • 系統先尊重逐字稿提及的人，再用職責表補位。
  • 審核後一鍵建立 GitLab issue 與 Slack 派工摘要。
  • 每個任務保留派工依據，方便稽核與回溯。
核心不是代替 PM，而是把 PM 的判斷流程制度化03
03 / Workflow從貼上到派發

Operating Flow

五段式審核派工流程

保留人工審核門檻，先讓 AI 做整理、推理與候選派工，再由管理者確認後觸發外部系統。

01

貼會議記錄

人工貼上逐字稿或摘要，保留原始上下文。

02

AI 拆解

抽出任務、期限、優先級、風險與建議 owner。

03

職責路由

比對 XLSX 人員職責表，以模組、關鍵字與角色分派。

04

審核修正

管理者檢查派工依據、高風險項與外部整合狀態。

05

同步監工

建立 GitLab issue，並在 Slack 群組發布摘要與提醒。

Review first, dispatch after approval04
04 / Positioning專案助理，不是聊天機器人

Product Position

企業會議到執行的控制台

它的第一畫面不是聊天框，而是可審核的管理台：貼記錄、看拆解、看派工依據、確認整合就緒，再推進到 GitLab 與 Slack。

Agent AI 做「解析與建議」，人做「核准與責任確認」，外部系統做「紀錄與催辦」。
適合分級自動化：從人工核准到半自動提醒05
05 / Capabilities現有核心功能

Capability Map

已完成的產品骨架

逐字稿 AI 拆解

支援 Anthropic gateway 與 OpenAI 風格 provider 設定，使用者自行輸入 API key。

真正提及的人優先

若逐字稿明確提到負責人，系統保留該 owner，並標記派工來源為逐字稿。

XLSX 職責表匯入

匯入公司人員、GitLab 帳號、Slack mention、角色、模組、關鍵字與備援人。

GitLab issue 建立

審核後建立 issue，若能解析使用者，會嘗試派給對應 assignee。

Slack 派工與催辦

產生群組摘要與提醒訊息，送出前保留人工確認，避免誤發企業大群。

整合就緒檢查

UI 顯示 AI、GitLab、Slack 缺少哪些欄位，降低 Demo 與導入時的設定錯誤。

每項能力都以「可審核、可追蹤、可回溯」為前提06
06 / Governance大企業導入控制點

Enterprise Guardrails

企業不是只要自動化，也要管控自動化

產品把關鍵風險點放在可見位置：誰被派工、為什麼被派、哪個整合缺設定、是否需要人工覆核。

已具備

派工依據

每張任務卡顯示「逐字稿」或「職責表」來源與理由，方便回溯。

已具備

高風險標記

客戶資料、法務、跨團隊發布等工作會要求更高審核注意。

已具備

API key 模式

使用者自行接入 key，後端只用於當次請求，不寫入 repo 或伺服器檔案。

待接入

正式權限與排程

需要企業 SSO、資料庫、長期排程器與正式 Slack user ID 對照。

治理能力先於全自動化，才能進入企業場景07
07 / Architecture目前整合架構

System View

單一管理台，連接三個執行面

Web 管理台 貼會議記錄、匯入職責表、審核 AI 拆解、查看整合就緒。
Session Secrets 使用者輸入 provider token，瀏覽器只保留目前 tab session。
Express API 任務解析、責任路由、GitLab issue、Slack message dispatch
AI Provider Anthropic gateway 或 OpenAI 相容設定，輸出結構化任務。
GitLab 建立 issue、附上 owner、deadline、priority、風險與原始摘要。
Slack 向公司群組發布派工摘要，後續可擴充提醒排程。
目前為單機 MVP 架構，正式版需加入 DB、Auth、Audit Log08
